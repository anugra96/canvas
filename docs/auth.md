# Sign-in and workspaces, iteration 1

Status: Proposed (spec agreed 2026-11-16, not built). Needs a security review
(Aegis) of this spec before implementation and of the diff before merge.

## Goal

Several real users can sign in, and each sees only the canvases of their
workspace. Nothing else. This iteration replaces the hard-coded `local-dev`
token and the unused Cognito path, and stays small enough to make solid before
more features are added.

## Today

| Part | Current state |
| --- | --- |
| API | `requireCanvasPrincipal()` in `api/src/auth.ts` accepts only `Bearer local-dev` and returns tenant `local` |
| Web | `web/src/auth/auth.ts` has a Cognito sign-in (`amazon-cognito-identity-js`) and a mock session; the client sends the token as a bearer header |
| Stores | Already scoped by `tenantId`; no change needed |
| Stack | nginx serves the web app and proxies `/v1/` to the API (same origin) |

## Scope

| In | Out (next iteration) |
| --- | --- |
| Email and password users, created by a seed script | Public sign-up, password reset, email verification |
| Cookie sessions; sign-in page; sign-out | Session list and revoke |
| Workspaces (tenants) with memberships; every member can edit | Owner, editor, viewer roles |
| Members added by script | Invite links, members page |
| Workspace switcher in the avatar menu, shown only with two or more workspaces | Workspace in the URL (`/w/<slug>/canvas/<id>`) |
| Dev token behind a flag, for agents and scripts | Per-user API tokens |
| | "Edited by" on canvases, activity log, single sign-on |

## Design

```text
browser ──cookie──> nginx ──/v1/auth/*──> API: Better Auth ──> Postgres (users, sessions, workspaces)
                          └─/v1/canvases─> API: requireCanvasPrincipal(session) ──> canvas store (tenant = active workspace)
agents  ──Bearer dev token (flag only)──> API ──> dev user, workspace "local"
```

- **Library:** Better Auth inside the Hono API, with its email and password
  method and its organization plugin. An organization is a workspace. Pin the
  version and follow its documentation for that version. Do not write password
  hashing or session handling by hand.
- **Database:** Postgres in the Docker stack, image pinned by digest, its own
  volume `canvas-postgres`, no host port unless `CANVAS_POSTGRES_PORT` is set
  (then bound to `CANVAS_BIND_HOST`). Tables are the library's standard ones:
  user, account, session, verification, organization, member. Migrations are
  generated by the library CLI, committed, and applied by a one-shot `migrate`
  service before the API starts (the same pattern as `minio-init`).
- **Mount point:** auth routes at `/v1/auth/*`, so the existing nginx `/v1/`
  proxy covers them. The Vite dev server proxies `/v1` to the API so the dev
  setup is also same-origin.
- **Principal:** `requireCanvasPrincipal()` keeps its signature and becomes:

  ```ts
  interface CanvasPrincipal {
    subject: string      // user id
    displayName: string
    email: string
    tenantId: string     // session's active workspace id
  }
  ```

  It returns 401 without a valid session, and 403 when the user is not a member
  of the active workspace. `groups` and the `canvas-editors` check are removed.
- **Workspace switch:** the switcher sets the session's active workspace and
  reloads the canvas list. A canvas link from another workspace returns 404 with
  the message "This canvas is not in the current workspace."
- **Existing data:** canvases already stored under tenant `local` must appear in
  the dev workspace without moving any object. The seed creates that workspace
  with id `local`.
- **Dev token:** `CANVAS_AUTH_ALLOW_DEV_TOKEN=true` lets `Bearer
  <CANVAS_DEV_TOKEN>` act as the dev user in workspace `local`. The API refuses
  to start when the flag is on and `CANVAS_ENV=production`. The local compose
  file turns it on so Codex and opencode imports keep working.
- **Removed:** `CANVAS_AUTH_MODE`, the Cognito sign-in, and the
  `amazon-cognito-identity-js` dependency. The web mock mode for unit and E2E
  tests stays.

## Security requirements

| Risk | Requirement |
| --- | --- |
| Session theft | Cookie `HttpOnly`, `SameSite=Lax`, `Secure` when served over HTTPS; session expiry from the library defaults |
| Cross-site requests | Mutating canvas routes check `Origin` against `CANVAS_TRUSTED_ORIGINS`; auth routes use the library's trusted-origins check; CORS is off in the stack (same origin) and never `*` with credentials |
| Password guessing | The library's rate limit on sign-in is on |
| Secrets | `CANVAS_AUTH_SECRET` is required at startup (fail fast). Secrets and seed passwords come from `.env`, which git ignores; `.env.example` lists names only |
| Tenant leak | Every canvas route takes the tenant only from the principal, never from the request |
| Dev token in production | Startup refuses it, as above |

## Local testing

`make seed-users` creates users and memberships (idempotent):

```text
alice  → workspace "Alice", workspace "Shared"
bob    → workspace "Bob",   workspace "Shared"
dev    → workspace "local"  (the existing canvases)
```

Passwords come from `CANVAS_SEED_PASSWORD` in `.env`. To test two users at once,
sign in as Alice in a normal window and as Bob in a private window.

## Proof

| Risk | Proof |
| --- | --- |
| Unauthenticated access | API test: every `/v1/canvases` route returns 401 without a session |
| Tenant leak | API test: Alice cannot list, get, save, or delete a canvas in Bob's workspace; both see Shared |
| Non-member access | API test: an active workspace the user is not a member of returns 403 |
| Dev token leak | API test: the token is refused when the flag is off; startup fails with the flag on in production |
| Cross-site write | API test: a save with a foreign `Origin` is refused |
| UI flow | E2E (production build against the stack): Alice signs in and creates a canvas; Bob, in a separate browser context, signs in and does not see it; both see a canvas in Shared |
| Data kept | Readback: after the upgrade, the dev workspace lists the same canvas count as before |

Auth tests run against a real Postgres, not a mock of the library.

## Rollout

1. Back up the MinIO volume as before. Never run `docker compose down -v`.
2. Build and start the stack; `migrate` creates the auth tables; run
   `make seed-users`.
3. Sign in as dev and confirm the existing canvases are listed (the readback
   above).
4. Update `docs/deployment-platform.md`: sign-in is in-app with Better Auth and
   Postgres; single sign-on is a later plugin; the stack has a second stateful
   service.
