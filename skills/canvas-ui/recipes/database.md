# Recipe: design a PostgreSQL database by hand

Profile: Database. Order matters: enums and tables first, foreign keys after
both tables exist.

```text
Create canvas (Database) → Database card → Enums → Tables (columns, PK, checks, indexes)
  → Foreign keys → Schema descriptions → Tidy database layout → Export DDL → compare
```

## 1. Database card

1. `Add` → `menuitem "Database"`. Open it: double-click `[aria-label="Database Database"]`.
2. Fill `Name` (required), and as needed `Server version` (e.g. `16`), `Owner`,
   `Extensions` (one per line: `pgcrypto public` = extension and schema). Click `Done`.
3. `Extra DDL` is read-only. It holds statements from `Import DDL` only.

## 2. Enum

1. `Add` → `menuitem "Enum"`. The new card is selected: double-click
   `.react-flow__node.selected` at once, before anything changes the selection.
2. Fill `Name`, `Schema`, `Values` (one value per line, order kept). Click `Done`.
3. Use it as a column type: `<schema>.<enum>`, e.g. `app.task_status`. A default
   is SQL text, so quote literals: `'open'`, not `open`.

## 3. Table

1. `Add` → `menuitem "Table"` opens `dialog "Add table"`.
2. Fill `Table name`, `Schema` (default `public`; a new schema creates its lane),
   select `Id column`: `uuid default gen_random_uuid()` or `bigint identity`
   (creates `GENERATED BY DEFAULT AS IDENTITY`; set `Column 1 identity` to
   `always` in the editor for `ALWAYS`).
3. Click `button "Add table"` (exact). The table appears in its schema lane
   with starter rows `id` (PK) and `created_at timestamptz not null default now()`.
4. Open it: double-click `[aria-label="Table <schema>.<name>"]` →
   `dialog "Edit Table"`.

### Edit Table fields

| Area | Labels (N is 1-based) |
| --- | --- |
| Table | `Name`, `Schema`, `Status`, `Description` |
| Columns | `Column N name`, `type`, `nullable` (checkbox), `default`, `primary key` (checkbox), `unique` (checkbox), `identity` (select: `""`, `by_default`, `always`), `generated`, `comment` |
| Column actions | `button "Add column"`, `Move <col> up`, `Move <col> down`, `Remove <col>` |
| Unique constraints | `button "Add unique"`, `Unique N name`, `Unique N columns` (comma-separated), `Remove unique N` |
| Checks | `button "Add check"`, `Check N name`, `Check N expression`, `Remove check N` |
| Foreign keys | `button "Add foreign key"`, `Foreign key N columns`, `Foreign key N table` (select `schema.table`), `Foreign key N referenced columns`, `Foreign key N on delete`, `Foreign key N on update` (select `no_action`, `restrict`, `cascade`, `set_null`, `set_default`), `Remove foreign key N` |
| Indexes | `button "Add index"`, `Index N name`, `Index N unique` (checkbox), `Index N method`, `Index N columns`, `Index N where`, `Remove index N` |

Rules:

- **Edit the starter rows; do not remove them all.** Rename row 1 and row 2,
  then `Add column` for each further column. Removing the last column shows the
  alert "A table needs at least one column."
- New columns start **nullable**. Uncheck `Column N nullable` for NOT NULL.
- To remove a default (for example on a reused starter row), clear the field: an empty default is dropped.
- Setting `identity` clears the default. Set identity before other fields.
- Composite primary key: check `primary key` on each column.
- `Column N unique` makes an unnamed single-column unique. For a named unique
  (`member_email_key`) or a composite one, use `Add unique` and leave the
  checkbox unchecked.
- Defaults, checks, generated columns, and index `where` are SQL text: quote
  string literals (`'active'`), write functions as called (`now()`, `CURRENT_DATE`).
- Index `columns` is comma-separated; an expression goes in parentheses:
  `(lower(email))`. A partial index uses `where`: `status <> 'done'`.
- `generated` takes the expression only: `(estimate_minutes / 60.0)` becomes
  `GENERATED ALWAYS AS (...) STORED`.

## 4. Foreign keys

Create both tables first. Then open the child table:

1. `button "Add foreign key"`. A valid row appears that targets an existing table.
   With only one table the button is disabled ("Add another table first").
2. Set `Foreign key N columns` (child columns, comma-separated),
   `Foreign key N table` (select `schema.table`), `Foreign key N referenced columns`
   (defaults to the parent primary key), `on delete`.
3. `Done`. The card shows `FK` on the column and a `references` line to the parent.

Drawing a line from a child column handle to a parent column handle also
creates the foreign key. Prefer the form: it is exact.

## 5. Schema description

`Fit View`, then double-click the lane title `[aria-label="Schema <name>"] header strong`.
Fill `Description`, `Done`.

## 6. Finish

1. `More canvas actions` → `Tidy database layout`.
2. `More canvas actions` → `Export DDL` (download) or `Copy DDL`.
3. Compare by meaning, not text. Export writes foreign keys as trailing
   `ALTER TABLE ... ADD CONSTRAINT ... FOREIGN KEY`, puts `DEFAULT` before
   `NOT NULL`, and may spell casts differently. The safe check: the DDL contains every table, `PRIMARY KEY`, `FOREIGN KEY ... ON DELETE`,
   `UNIQUE`, `CREATE INDEX`, `CHECK`, and `COMMENT ON` you designed.

## Failure signs

| Sign | Meaning |
| --- | --- |
| Card shows "Double-click to add columns." after an edit | The edit did not save. Reopen and read the alert |
| `getByLabel('Column N ...')` not found | Row N does not exist yet: click `Add column` |
| Double-click opens nothing | The card is off-screen or under a dialog. Press `Escape`, click `Fit View`, retry |
